ft-asr track — part 1: build the ASR adapter

Improve --sent-4 by replacing the witness generator. The labeler's four beam hypotheses currently come from the untuned base omni model; here a LoRA is fine-tuned to do ASR and nothing else, and that adapter produces the hypotheses the key-piece loss labels are derived from. Everything downstream (SFT prompt, judge, metric) is held fixed, so a change in EAR is attributable to label quality.

Part 1 · ASR data + adapter (steps 0–5) Part 2 · witness swap, gate, sent4-v2 (steps 6–12)

Decisions on record

ASR training data — fresh mixes, uniform SNR.
Not a reuse of sent4-v1 rows: those SNRs are clumped into the kind bands, and their sentences are the ones the labels get built from. A new set over SLURP devel is both better-conditioned and leakage-free (see §leakage).
Beam diversity — keep 4 beams, but measure the collapse.
Fine-tuned ASR models often return four identical beams, which silently turns “lost only if every witness missed it” into a one-witness rule. Step 8 in part 2 is a hard gate on that number.
Scope — labeler only.
sft_qwen.py and babble_eval_qwen.py keep running the unmodified base model. One variable moves.
Config — one track YAML, every stage reads it.
configs/ft-asr.yaml. Additive: the HR=/TREE=/SENT4= env-var paths in sft.sh, eval.sh, babble_data.sh are not touched, so no existing track's argv changes.

Where the adapter plugs in

The only structural change is the box in red. Read the two columns against each other — every other stage is byte-identical to the sent4-v1 run.

Step 0 — preflight: is devel really disjoint?

The whole leakage argument rests on one claim: babble_data.py only ever reads SLURP train and test (babble_data.py: build_triplets("test", …), build_triplets("train", …), collect_babble_pool), so an adapter trained on devel has heard neither the sentences its witnesses will be judged on nor the ones the sent-4 labels are derived from. SLURP partitions by prompt, so this should hold on sentences too. Verify before spending a GPU hour on it.

Why not just reuse the sent4-v1 train rows, which already carry noisy audio + a clean sentence?

Two reasons, one methodological and one about conditioning.

Leakage. Those rows are drawn from SLURP train, which is exactly the pool build_triplets("train", …) draws the sent4-v2 rows from. The ASR adapter would have memorized the sentences whose key pieces it is then asked to witness. Its transcripts on train rows would look better than they are, pieces would read as recovered, and the label distribution would shift toward answer for a reason that has nothing to do with hearing.

Conditioning. The sent4 SNRs are clumped into the three kind bands (SLOT_SNR_DISJOINT: 12–20 / 5–12 / 0–5 dB) and 25% of the answer rows are clean. An ASR model trained on that mixture sees a trimodal noise distribution; a uniform 0–20 dB sweep is the right training distribution for a model whose job is to be honest at every SNR.

Step 1 — the track config

configs/ft-asr.yaml new

One flat file, unique keys, the whole track. Every value a stage needs is written here explicitly rather than inherited from a script default — that is the point: sent4-v1's reproduction broke because its prompt lived in a Python default that later moved. A value written in this file stays right no matter what the default becomes.

Every key has exactly one field and exactly one CLI flag that overrides it — no renaming, no merging, no prefix rules in the loader. The only structural wrinkle is that sft_qwen.py runs twice off the file (the ASR witness adapter, then the repair adapter), so the values that differ between its two runs are spelled both ways — asr_epochs and repair_epochs, and likewise *_ds_id, *_lr, *_repo_name — and --task decides which set that script reads. task itself is deliberately not in the file, since one file cannot answer it for both runs; it is the one value that always comes from the command line. That decision lives in sft_qwen.py, where the two runs are, and nowhere else.

util.py: load_config edit

Six call sites, so it belongs at module level (CLAUDE.md's rule). Each stage declares its own @dataclass Config — the stage's surface and its defaults in one readable block — and this builds one from the flat file. Field names are the YAML key names, so there is no mapping table to drift out of sync.

def load_config(path, cls):
    """Build a stage's config dataclass from a flat track YAML.

    Three layers, each overriding the one before: the dataclass holds the
    defaults, the file overrides them, and the CLI overrides the file (see any
    stage's __main__). The dataclass is the only place a default is written --
    argparse holds none, so there is nothing to keep in sync.

    Field names are the YAML key names. Keys a stage does not declare are not
    its business: one flat file serves the whole track, so every stage reads
    the handful it declares and ignores the rest. A script that needs two sets
    of the same value declares both and picks between them itself -- that
    choice belongs to the script, not here.
    """
    import yaml  # only the config path needs it; keep it off the import cost
                 # of every training job that doesn't pass --config

    with open(path) as f:
        raw = yaml.safe_load(f) or {}
    names = {f.name for f in dataclasses.fields(cls)}
    return cls(**{k: v for k, v in raw.items() if k in names})

The shape every stage's __main__ uses

One structure, four scripts. The config object is resolved first and the CLI overrides it — the CLI does not set argparse defaults.

    """This stage's surface. The ONLY place a default is written."""

    n_rows: int = 8000

if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--config")
    # No default= anywhere: argparse already stores None for an absent flag,
    # and None-means-absent is the whole distinction the override loop keys on.
    ap.add_argument("--ds-id")
    ap.add_argument("--n-rows", type=int)
    # the one exception -- store_true defaults to False, which would read as
    # "passed" and overwrite the file's value on every run
    ap.add_argument("--no-push", action="store_true", default=None)
    args = ap.parse_args()

    cfg = load_config(args.config, Config) if args.config else Config()
    for key, value in vars(args).items():
        if value is not None and key != "config":
            setattr(cfg, key, value)

    main(cfg)
One helper, three layers. load_config is the only config function in util.py: it reads the file, and the loop above applies the CLI on top. Defaults live in one typed block per stage instead of thirty default= kwargs scattered down a parser, and main(cfg) stays callable from a notebook or another script with a hand-built Config. The cost is the discipline above — no flag may carry a default= other than None, and the store_true flags must say it explicitly, or the override loop reads an absent flag as a passed one.
The one sharp edge: booleans only turn on. With action="store_true", default=None, a flag can override False in the file but nothing can override True from the CLI. Where that matters, use action=argparse.BooleanOptionalAction, default=None (Python 3.9+), which gives you both --push and --no-push off one declaration and still reports None when neither is passed.
A misspelled key is inert — read the resolved config. That is the price of one flat file serving six invocations: each stage legitimately ignores 15–20 keys that belong to the others, so there is no per-stage list of “unknown” keys worth printing — a typo would be buried in it. What catches it instead is log(f"config: {cfg}") right after the override loop: a typo'd key leaves its field sitting at the dataclass default, visible in one line at the top of every log. Read it on the first run of each stage.
Moving an existing script's defaults is the risky part. For sft_qwen.py and babble_data.py, every current default= has to be transcribed into the dataclass exactly — miss one and an existing track's behaviour changes even though nothing about its command line did, which is the one thing this plan promised not to do. Do the move by diffing, not by memory, and log the resolved config on startup so the first run of each existing track shows its own settings:

Step 3 — asr_data.py new

Uniform-SNR babble mixes over devel, drawn by util.add_noise — the same function babble_data.probe_by_kinds mixes with, so the two datasets differ in their SNR distribution and in nothing else. No GPU pass, no LLM call, no probing loop — the transcript is the ground truth, so there is nothing to label. It writes the target column as the normalized sentence, which is what makes step 4 a six-line change instead of a new Dataset class: SlurpDataset already reads row["target"].

from babble_data import (
    AUDIO_ROOT,
    AUDIO_SAMPLING_RATE,
    MAX_AUDIO_SECONDS,
    MIN_AUDIO_SECONDS,
    SEED,
    collect_babble_pool,
    log,
    slurp_ds_stream,

from util import add_noise, load_config

NORMALIZER = BasicTextNormalizer()
ROW_ID = itertools.count(1)
MIN_WORDS = 2


@dataclass
class Config:
    slurp_split: str = "devel"
    asr_ds_id: str = "keylazy/slurp-asr-bab-v1"
    asr_n_train: int = 8000
    snr_db: tuple = (0.0, 20.0)
    clean_prob: float = 0.15
    draws_per_utt: int = 1
    # slurp_id % test_every == 0 -> held out. Not a tail slice: slurp streams
    # every recording of one prompt back to back, so a positional boundary puts
    # the same sentence on both sides of the split.
    test_every: int = 20
    no_push: bool = False


def build_splits(cfg: Config, audio_dir) -> tuple[list[Any], list[Any]]:
    """
    Return train and test rows
    """

    train, test = [], []

    bab_pool = collect_babble_pool(cfg.slurp_split)

    skipped = 0
    pbar = tqdm(total=cfg.asr_n_train, unit="row", dynamic_ncols=True)
    max_len = MAX_AUDIO_SECONDS * AUDIO_SAMPLING_RATE
    min_len = MIN_AUDIO_SECONDS * AUDIO_SAMPLING_RATE

    for i, slurp_row in enumerate(slurp_ds_stream(cfg.slurp_split)):
        if len(train) >= cfg.asr_n_train:
            break

        sentence = NORMALIZER(slurp_row["sentence"]).strip()
        clean = slurp_row["audio"]["array"].astype(np.float32)[:max_len]
        if len(sentence.split()) < MIN_WORDS or len(clean) < min_len:
            skipped += 1
            continue

        sid = slurp_row["slurp_id"]
        pool = [aud for pool_sid, aud in bab_pool if pool_sid != sid]
        is_test = sid % cfg.test_every == 0
        bab_rng = random.Random(f"{SEED}:asr:{i}")

        for _ in range(cfg.draws_per_utt):
            rid = next(ROW_ID)
            path = os.path.join(audio_dir, f"{rid:06d}.wav")
            if bab_rng.random() < cfg.clean_prob:
                # keep noise-free audio in the mix, which is the common case in
                # deployment; snr_db=None reads as "clean" everywhere downstream
                audio, snr = clean, None
            else:
                audio, snr = add_noise(clean, pool, cfg.snr_db, bab_rng)
            sf.write(path, audio, AUDIO_SAMPLING_RATE)
            row = {
                "id": rid,
                "target": sentence,
                "kind": "asr",
                "audio": path,
                "snr_db": snr,
                "sentence": sentence,
                "slurp_id": sid,
                "source": "asr-babble",
            }
            (test if is_test else train).append(row)
            if not is_test:
                pbar.update(1)

    pbar.close()  # stream done
    log(f"skipped {skipped} (too short / <{MIN_WORDS} words)")

    return train, test


def main(cfg):
    log(f"config: {cfg}")

    audio_dir = os.path.join(AUDIO_ROOT, cfg.asr_ds_id.split("/")[-1])
    shutil.rmtree(audio_dir, ignore_errors=True)
    os.makedirs(audio_dir, exist_ok=True)
    log(f"audio dir: {audio_dir}")

    train, test = build_splits(cfg, audio_dir)
    rows_json = os.path.join(audio_dir, "rows.json")
    with open(rows_json, "w") as f:
        json.dump(
            {"config": asdict(cfg), "train": train, "test": test},
            f,
            indent=1,
        )
    log(f"wrote {rows_json}")

    snrs = [r["snr_db"] for r in train if r["snr_db"] is not None]
    log(
        f"train {len(train)} / test {len(test)} rows; "
        f"clean {sum(1 for r in train if r['snr_db'] is None)}; "
        f"snr mean {np.mean(snrs):.1f} min {min(snrs):.1f} max {max(snrs):.1f}"
    )

    # built either way, so --no-push still exercises the Audio cast and the
    # schema inference a push would hit
    dsd = DatasetDict(
        {
            split: Dataset.from_list(rows).cast_column(
                "audio", Audio(sampling_rate=AUDIO_SAMPLING_RATE)
            )
            for split, rows in (("train", train), ("test", test))
        }
    )
    if cfg.no_push:
        log(f"--no-push: built {cfg.asr_ds_id} locally, see {rows_json}")
        return
    dsd.push_to_hub(cfg.asr_ds_id)
    log(f"pushed {len(train)} train / {len(test)} test rows to {cfg.asr_ds_id}")

The mixing math is not duplicated here. util.add_noise(clean, pool, snr_band, rng) holds it and both builders call it: this one with a single 0–20 dB band, probe_by_kinds with the per-kind band of the slot it is drawing for. pool is a plain list of clips, so each caller drops the utterance's own recording before passing it in — [aud for pool_sid, aud in bab_pool if pool_sid != sid]. The clean-audio draw stays with the caller, because what fraction is clean and which rows are eligible is each track's own policy (clean_prob here, CLEAN_ANSWER_PROB on the answer slot there).
sbatch --wrap runs its string under sh, not bash. So --wrap='source ~/.bashrc; conda activate ...' dies before conda is ever on PATH — ~/.fzf.bash uses process substitution, which sh cannot parse. Two forms work, and every sbatch in this doc and in part 2 uses one of them:
  • One-off from the shell — --wrap="bash -lc '…'". The login shell reads ~/.bashrc itself, under bash, so conda activate works. Note the quote flip: double outside, single inside, and $CONDA_PREFIX escaped as \$CONDA_PREFIX so it expands in the job rather than in your submitting shell.
  • Anything with more than one command — put the body in a #!/bin/bash file that sources ~/.bashrc itself and --wrap='./exp/<name>-run.sh'. That is what exp/ft-asr.sh / exp/ft-asr-run.sh do.

Step 4 — sft_qwen.py: --task asr + --config edit built

Because asr_data.py writes the transcript into target and SlurpDataset already reads row["target"], the only thing that has to change at train time is which prompt pair the collator renders. As built, that is one call.

4a. The collator asks prompts.get_prompts for its pair

The plan drafted an if task == "asr" branch inside OmniSFTCollator.__init__ that reassigned self.task_prompt and conditionally self.system_prompt. It landed as a lookup instead — get_prompts(task, family) in prompts.py returns the (system, user) pair, and owns both rules that branch was re-deriving: which family takes a system prompt at all (qwen3 takes none, per its model card) and which user prompt goes with the job. The collator therefore takes family, not a pre-resolved system_prompt:

class OmniSFTCollator:
    def __init__(self, processor, family, task="repair") -> None:
        self.processor = processor
        # must match the prompts the dataset's targets were built under, and
        # the ones babble_eval_qwen.py evaluates with
        self.system_prompt, self.task_prompt = get_prompts(task, family)

Same reasoning as the drafted comment, in one place instead of at every call site: the ASR adapter's only consumer is babble_data.py's probe pass, which decodes under this exact pair, so a different framing here is a train/probe mismatch and the witness gets worse rather than better. run_smoke takes family and task and builds its collator the same way, so --smoke works on both tasks.

4b. Config, flags, and the repair_*/asr_* pairs

Every value that differs between the two runs is a repair_*/asr_* pair, and main() picks a side off cfg.task. Renames against the plan — the flag names are the field names are the YAML keys, so these three move together:

PlanAs builtWhy
ds_id / asr_ds_idrepair_ds_id / asr_ds_idBare ds_id in the track file is babble_data.py's output id. Leaving the repair run on the unprefixed key would have made one YAML key mean two things.

The bug the None-default discipline exists to catch, caught three times. The first cut of this step kept default=16 on --batch-size, default="repair" on --task, and a bare action="store_true" on --smoke. None of those is ever None, so the override loop reads every run as having passed the flag and the config file's value is overwritten on every single run — task: asr in a YAML would have been unreachable, and batch_size in the file inert. Every flag now carries no default= at all, or default=None for the two store_trues.
And the rename bug. The field was repair_epoch while the flag was --repair-epochs. setattr does not care: the flag quietly created a new attribute nobody read, and the run trained for the dataclass's 3 epochs no matter what was passed. Nothing raises on this class of typo — the print(f"config: {cfg}") now at the top of main() is what shows it, because the field sits at its default in a line you can read.

4c. The guard: a flag for the run you are not doing

Each key has exactly one flag, so a hand-passed --repair-lr on a --task asr run would be read by nobody. Say so in the first second rather than twelve hours in:

    other = ("repair_", "asr_") if cfg.task == "asr" else ("asr_", "repair_")
    ignored = [
        k for k in vars(args) if k.startswith(other[0]) and getattr(args, k) is not None
    ]
    if ignored:
        raise SystemExit(f"--task {cfg.task} reads {other[1]}* keys, not {ignored}")

4d. Fallout in the drivers

The plan promised “every existing track keeps its exact argv”. That promise did not survive the renames, and sft.sh was left passing --ds-id --run-name --epochs, none of which exist any more — an unrecognized arguments exit on every track, before the model loads. Fixed at both call sites:
