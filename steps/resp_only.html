Response-only labeling

Drop the ASR probe pass entirely. Make the task prompt ask the model to ground its reply in what it heard, and let that single reply carry all the survival evidence — for the classifier, for target writing, and at eval.

Decisions taken (from the pre-plan questions)
  • Prompt scope: everywhere. The grounded prompt is used by the data-gen probe, by SFT, and at eval — train and test framing stay matched. This cascades into target style and into what the eval judge sees.
  • Response shape: naturally grounded reply. One natural sentence or two that names the request's details back. No Heard: … / Reply: … scaffolding in the output format.
  • Target generation: conditioned on base replies instead of ASR transcripts.
  • Plumbing: --resp-only flag on babble_data.py — one code path, both variants runnable, prompt variants side by side in prompts.py. Existing baseline datasets stay byte-reproducible.

Why the prompt change is load-bearing, not cosmetic

The two-pass design exists because a task reply is a lossy witness of what was heard: “Sure, I'll take care of that” proves nothing about any piece. The transcript was the fallback witness. Remove it and a generic reply becomes indistinguishable from total loss — every such row lands in repeat. The grounded prompt is what makes the single witness informative enough to replace two: it forces the reply to name the action and the entities/times/quantities it caught, so the classifier can check each key piece against the reply alone.

Constraint: the grounded prompt must not mention clarifying questions or repair. Whether the base model asks a targeted question when a piece is missing is exactly what the benchmark measures; instructing it to would contaminate both the labels and the eval baseline. It adds restatement only.

Steps

1Free dry run first: replay the classifier over data you already have

Before touching a GPU. The existing datasets already store the base model's reply per row in the omni_response column, alongside the two-pass kind label. So the new response-only classifier can be scored against the old labels for the cost of some vLLM calls:

load keylazy/slurp-babble-Qwen2.5-Omni-3B-v3 (train)
for each row: classify_resp(sentence, omni_response) -> kind'
report: agreement rate, and the confusion kind -> kind'

This tells you the single most important unknown — how much does dropping the transcript move the labels, and in which direction — before spending a full regeneration run. Expect the drift to be concentrated in answer → repair and repair → repeat (evidence removed can only ever make a row look harder, never easier).

Read it as a lower bound, not the real number. Those stored replies were produced under the old prompt, so they are exactly the uninformative-witness case the grounded prompt is meant to fix. Real agreement after the prompt change will be higher than what this dry run shows. Use it to size the problem and to debug the new rubric's wording on concrete cases (grep the rows where kind' == "repeat" but kind == "answer" — those should almost all be generic replies).

2prompts.py: two named prompts plus a selector

Keep the existing constant untouched so the baseline track stays reproducible; add the grounded variant beside it.

TASK_PROMPT = (
    "You are a smart voice device with full access to the user's apps, "
    "accounts, devices, information, and the internet. Listen to the user's spoken "
    "request and respond naturally and concisely, addressing everything it asks."
)

# --resp-only track: the reply is the ONLY witness of what got through the
# noise, so it has to name the details back. Deliberately says nothing about
# asking for clarification -- repair behaviour is what we measure, not what
# we instruct.
TASK_PROMPT_GROUNDED = (
    "You are a smart voice device with full access to the user's apps, "
    "accounts, devices, information, and the internet. Listen to the user's spoken "
    "request and respond naturally and concisely, addressing everything it asks. "
    "Ground your reply in what you actually heard: name the specific details of the "
    "request back to the user -- the action, and any names, places, times, dates, "
    "or quantities you caught -- so it is clear what you understood. Do not invent "
    "a detail you did not hear."
)


def task_prompt(grounded: bool) -> str:
    return TASK_PROMPT_GROUNDED if grounded else TASK_PROMPT

“Do not invent a detail you did not hear” matters: a bare restatement instruction invites the model to confabulate a plausible-sounding detail to satisfy the format, and a confabulation with no acoustic basis is pure label noise. A genuine mishearing is different — that is signal, and it will still surface.

3babble_data.py: the --resp-only path

3a. Skip the ASR pass in probe_triplet. The two base_generate_batch calls collapse to one:

# two-pass (current)
convs = [_conv(a, ASR_SYSTEM_PROMPT if base_family == "qwen2.5" else None, ASR_PROMPT) for a in audios]
transcripts = base_generate_batch(convs, ASR_MAX_NEW_TOKENS)
convs = [_conv(a, QWEN25_SYSTEM_PROMPT if base_family == "qwen2.5" else None, TASK_PROMPT) for a in audios]
responses = base_generate_batch(convs, RESP_MAX_NEW_TOKENS)

# --resp-only
transcripts = [""] * len(audios)          # keep the column, empty
convs = [_conv(a, QWEN25_SYSTEM_PROMPT if base_family == "qwen2.5" else None,
               task_prompt(RESP_ONLY)) for a in audios]
responses = base_generate_batch(convs, RESP_MAX_NEW_TOKENS)

Keeping asr_transcript as "" rather than dropping the column keeps the pushed schema identical to v3/v4, so babble_eval_qwen.py's row["asr_transcript"] and anything in eval.ipynb keep working against both tracks. classifier_reason also loses its Transcript: … | Reply: … shape and becomes the single reply evaluation.

3b. CLASSIFY_SYSTEM_RESP. Fork the rubric rather than parameterise it — the survival section changes character, not just wording. Keep verbatim: the key-info definition, the filler/wake-word exclusions, the “implied by the rest of the command” carve-out, the repair usefulness test, the repeat definition, the missing/misheard_as rules. Rewrite:

Current lineResponse-only replacement
“You will be given three texts … two independent passes over the same noisy audio”Two texts: COMMAND and REPLY. The reply is the only evidence of what got through, and the device was instructed to name back the details it heard.
“SURVIVED if the transcript contains it correctly … OR the reply demonstrates …”SURVIVED if the reply names it, paraphrases it, or otherwise demonstrates it was heard — including a capability-decline or hand-off that refers to it correctly. Keep the existing “judge understanding, not verbatim repetition” language.
“LOST only if BOTH passes missed it”LOST if the reply neither contains the piece nor demonstrates it was heard, or replaces it with a wrong word.
“The assistant asserting a wrong detail does NOT mark a piece lost when the transcript has that piece correctly — the transcript alone is sufficient proof of survival.”Delete. With one witness this inverts: a confidently asserted wrong detail is now the primary evidence that the piece was lost.
“Singular/plural, spelling … in the transcript count as survived, even if the reply heard something else”Reframe onto the reply: minor wording, paraphrase, singular/plural and spelling differences in the reply count as survived; a meaning-changing substitution does not.
“A correct reply always overrides a bad transcript”Delete (nothing left to override).
“COMMAND, TRANSCRIPT, and REPLY are all shown lowercase”“COMMAND and REPLY are shown lowercase …” — _normalize_text still applies to both.
“Evaluate the transcript and the reply SEPARATELY”One evaluation pass over the reply, still capped (“under 40 words”).

New rule to add, covering the failure mode this design creates:

- A reply that declines or deflects without naming ANY specific content word
  from the command ("i cant help with that", "sorry, i dont know") is NO
  EVIDENCE about any piece, not proof of survival. If the reply gives no
  evidence for any key piece, classify "repeat".

Output shape drops one field:

{"reply_evaluation": "<one short verdict per key piece, e.g. '7 am: missing; alarm: survived'>",
 "missing": [...], "misheard_as": "...", "kind": "answer" | "repair" | "repeat"}

classify()'s parsing shrinks accordingly (reason = reply_eval, no concatenation) and its retry guard on missing-vs-kind consistency is unchanged.

3c. TARGET_SYSTEM_RESP. Two edits beyond swapping transcripts for replies:

  • The answer target must itself be grounded. This is forced by the “prompt everywhere” decision — if SFT prompts the model to name details back but the gold answer is a generic “Sure, on it”, training actively unlearns the grounding the whole design depends on. Add to the answer rules: name the request's specific details back (the action plus any names, places, times, dates, quantities), then answer or confirm. The existing rules (address every part; direct facts when known; present/future tense; never claim the action is done; stay concise) all stay.
  • Withhold the repeat probe's reply entirely. Under response-only, the repeat probe's reply is typically a confident hallucination — and the repeat target's one hard requirement is that it hints at no content whatsoever. Feeding a hallucinated entity into the writer's context is a leak waiting to happen for zero benefit, since the writer only needs to know “too much was lost”. So TARGET_USER_RESP passes the repair reply and drops the repeat one: 
    TARGET_USER_RESP = (
    'COMMAND:\n"{sentence}"\n\n'
    'REPAIR-REPLY:\n"{repair_response}"\n'
    'LOST-PIECE: "{lost_span}"{swap_note}'
)
    and the repeat rules keep their existing “do NOT reference, guess, or hint at ANY content details” prohibition.

The repair rules need only a reframe: ground the question in the parts the REPAIR-REPLY got right, never reveal the lost piece, MISHEARD-AS confirmation questions stay optional. Note that misheard_as will fire less often now — mishearings are harder to spot in a paraphrased reply than in a transcript — so the “did you say saved or shared?” style will get rarer. That is a genuine loss in target diversity; the swap note is already conditional so nothing breaks.

3d. Wiring. --resp-only selects: the prompt, which classifier system prompt, which target system/user template, and whether the ASR batch runs. Default off. ASR_PROMPT/ASR_SYSTEM_PROMPT/ASR_MAX_NEW_TOKENS stay in the file, unused on this path.

4sft_qwen.py: delete the duplicated prompt first

Latent bug worth fixing regardless of this experiment. sft_qwen.py defines its own copy of TASK_PROMPT (around line 30) instead of importing from prompts.py. Today the two copies happen to be identical, so nothing is wrong — but the moment either is edited, training and eval silently prompt the model differently and nothing errors. Replace the local copy with from prompts import task_prompt before adding the flag.

Then add --grounded-prompt (default off), passed through to wherever the collator renders the user turn. Give the run a distinct output/hub name so it cannot overwrite the baseline adapter: Qwen2.5-Omni-3B-bab-resp-sft / keylazy/Qwen2.5-Omni-3B-bab-resp-sft-adapter. Run --smoke once after the change and confirm the supervised-token diagnostics still show only the assistant turn masked in — the longer prompt shifts the prompt/full token-length diff the label mask is built from, which is exactly what --smoke exists to catch.

5babble_eval_qwen.py: smaller change than it looks

The judge rubric needs no change. RESPONSE_TYPE_SYSTEM already scores (sentence, response) only — classify_response never saw a transcript. The scoring path, SCORE_MATRIX, and the C/R/F/EAR harmonic mean are all untouched. Four things do change:

  1. --grounded-prompt (required for this track). build_conversation must use the same prompt the model was trained under. Evaluating a resp-only adapter under the plain prompt is a train/test mismatch that will read as a regression.
  2. Output filename collision. The default is bab_results_{model_name}_v2.jsonl, keyed only on the model/adapter name — a resp-only run of a model you have already evaluated silently overwrites the baseline result file that eval.ipynb reads. Fold the track into the default name (…_resp.jsonl when the flag is set) or always pass --out.
  3. Defensive column read. row["asr_transcript"] → row.get("asr_transcript", "") (line ~405) and likewise omni_response at line ~425, so the script survives a future dataset built without those columns. With step 3a they are present-but-empty, so this is belt-and-braces; the ASR : print line just goes blank.
  4. --dataset must point at the resp-only test split. The labels differ, so the baseline test set is the wrong ground truth for this track.

Expect the confusion matrix to shift even with an identical rubric, for a reason unrelated to model quality: under the grounded prompt, the rubric's “capability-decline must restate a content word” test is now nearly always satisfied, so replies that used to land in bad as generic refusals now land in answer. Symmetrically, restated wrong details are far more visible, pushing hallucinations into bad. Both are intended effects of grounding — but they mean C/R/F/EAR from this track are not comparable to any previously recorded number, even for the same model on the same audio.

7Ten-triplet smoke run before the full build

Temporarily set N_TEST_TRIPLETS = 10, point --ds-id at a throwaway repo, and read the tqdm postfix counters:

  • skip["probe"] — how often MAX_PROBES=3 batches fail to yield one audio of each kind. This is the number most likely to blow up. SLOT_SNR's bands were tuned so that two-pass labeling produced the intended kind; with one witness removed the same SNR draw labels harder, so the answer slot becomes the scarce one. If skip["probe"] climbs well past the baseline rate, raise SLOT_SNR["answer"] (e.g. (8, 20) → (10, 22)) rather than raising MAX_PROBES — more probe batches cost GPU time linearly and do not fix a mis-centred band.
  • skip["targets"] — target-writer JSON failures; should stay near zero. Non-zero means TARGET_SYSTEM_RESP's new output contract is confusing the writer.
  • Then read ~15 generated rows by hand: does each answer target actually name details back? Does any repeat target leak an entity? Does the repair question avoid revealing the lost piece?

What this experiment can and cannot tell you

The headline comparison changes three things at once — label source (two witnesses → one), task prompt (plain → grounded), and target style (generic → grounded). So “resp-only beat baseline” would be a statement about the pipeline end to end, not about response-only labeling in isolation.

RunDataPromptTells you
baseline basev3/v4 testplainexisting numbers, unchanged

resp adapterresp-v1 testgroundednew track end to end

That ablation row is the highest-value single extra run here; without it a shift in EAR cannot be attributed to the labeling change at all.

Scope check: what does NOT change

  • make_probe_batch and the SNR/babble synthesis math — untouched.
  • RESPONSE_TYPE_SYSTEM, SCORE_MATRIX, harmonic3, the summary-record format — untouched, so eval.ipynb's load_summary parsing keeps working.
  • The pushed dataset schema — same columns, asr_transcript merely empty.
  • The EAR / word-masking track (slurp_sft_data_qwen.py, slurp_ear_eval_qwen.py) — unrelated, no ASR probe to remove.
  • Existing baseline datasets and adapters — new repo ids and new adapter names throughout, nothing overwritten.

Risks

Single witness is strictly less evidence. The grounded prompt is a mitigation, not a proof — a model that ignores the grounding instruction (likely for the smaller Qwen2.5-3B) produces uninformative replies and its rows drift toward repeat. Step 1's dry run plus the smoke run's kind distribution are how you catch this early; if Qwen2.5-3B's answer slot collapses, that is a finding about the model, not a bug.
The prompt is a confound, permanently. Because it applies at eval too, this track's numbers can never be placed in the same table as the baseline's without a footnote. Plan the paper table accordingly, or run the step-7 ablation and report it alongside.
Mishearing detection degrades. No transcript means misheard_as fires less, which thins out confirmation-style repair targets (“did you say saved or shared?”). Worth counting the misheard_as non-empty rate in the new dataset versus v3 to quantify.
Compute saving is real but modest. One prefill+decode of every probe audio disappears, but the removed pass was the cheap one (64 vs 256 max-new-tokens) and audio prefill dominates for short SLURP utterances. Do not budget on a 2× speedup; measure the smoke run's wall clock against the baseline's.
